## Friction points for a friend, ranked

1. BUG, hits the default folder name. The installer writes the game path unquoted into `.env` (`D2_GAME_DIR=/path/Diablo II`). Compose reads that fine, but `./didle` sources `.env` as shell: every `./didle` command (status, stop, start, update, report) dies with `./.env: line 3: II: command not found` for a path with a space, and `set -e` ends the script (V: reproduced; with the value quoted by hand all commands worked). The original install folder is named `Diablo II`, so most friends will hit this on the first `./didle status`. Fix: quote the value in `install.sh` (and in `didle`, read `.env` with a parser instead of `source`).
2. The unzip root contains the folder `Diablo II`; pointing `--game-dir` at its parent gives "missing ..." with no pointer. Fix: if the four files are one level down, say `found them in <dir>/<sub>; use --game-dir '<that>'` (or accept it).
3. The licence question comes before the game-folder checks, so a non-terminal run or a first wrong path prints the whole note first (already known, drill D1 of 2026-11-11), and the answer must be given in a real terminal (the wizard drills here used `script`).
4. The page URL printed by the installer is `http://localhost:PORT/setup.html?t=...`; the setup API answers `forbidden origin` to a request on `127.0.0.1` (by design, the origin must be the printed one), a trap for anyone scripting or opening the page by IP (the guide already says so).
5. README.txt says to check "this download" with `SHA256SUMS`, which only works after unpacking; the tarball's own `.sha256` (sent separately) is not mentioned there. Fix: one line "check the tarball with `sha256sum -c didle-friends-X.tar.gz.sha256` before unpacking".
6. The whole game folder, including the key file, is mounted read-only into the container (S: `D2_GAME_DIR` to `/game`). Nothing is known to read the key (U). Not a friction, but a privacy note: mount only the needed files, or say so in the guide.
7. The wizard API wants lowercase class ids (`paladin`) and the preset id `campaign:normal_act1`; the API error `unknown class "Paladin"` is clear. Only relevant to scripted use.

## Proposed fixes (ranked)

1. Quote `D2_GAME_DIR` in `.env` and make `didle` robust to spaces (small, container; also add a test with a space path in the pack tests). Needs a re-cut of the pack: ship it in 0.1.2 or note a one-line workaround for 0.1.1 friends (`edit .env: D2_GAME_DIR="..."`).
2. Installer: detect the `Diablo II` subfolder one level down and suggest or use it.
3. README.txt: add the tarball checksum command and the `Diablo II` folder name in the example.
4. Optional: mount only the MPQs the bot needs.
5. For the next drill: a newer test release signed by a throwaway key plus a DEV image (as in docs/friend-drills.md) to run D3/D4 on this exact game folder.
