## What changed for friends (plain words)

- Game folder privacy: the installer no longer mounts your whole game folder. It writes `compose.game.yml` with one read-only mount per data archive d2d reads (`d2data`, `d2exp`, `d2char`, `patch_d2`, `d2sfx`, `d2speech`, `d2xtalk`, `d2music`, `d2xmusic`; the list comes from the fork source: `gamedata_load.cpp` and `apps/d2d/main.cpp` read nothing else, and the video archives only when a video plays, which the headless friends build never does). The key file, the game program, DLLs, saves and everything else stay out of the container (V: a test with decoy `default.key`, `d2.key`, `Game.exe`, a DLL, a save and a video archive checks the generated files; the legal checklist item 1 now fails when `compose.yml` mounts the folder). The real container with real archives mounted file by file is U until the drills run.
- Installer: a game folder with a space in its name (the default "Diablo II" of the user's install zip) no longer breaks `./didle` (the path is quoted in `.env`; V: test sources `.env` under bash). Pointing `--game-dir` at the unzip root works: the installer finds the `Diablo II` folder one level down and says so. README.txt tells friends to check the tarball with its own `.sha256` first.
- Bot fixes merged since 0.1.1 (docs/releases/0.1.1.md lists the earlier ones): stale-target and quest-blocked fallback (the hero is no longer parked in town), sell-skip WearBetter fix, merc revive on gold alone, swing model, warp click point, level plan v3, loot rules, UI design updates. The merged cards and their records are the source of truth.
- d2d unchanged: fork `acadbe47f989` (branch `fork-only/art-clean`), byte-identical binary (sha256 `1a642471cdcd5539ef01a7c9518e4a0e9f734561570012d5d6fa4e2bd960f99e`), same source tarball as 0.1.0 and 0.1.1.

## Bot and pack d2d pair (S, read in the source; V on the pack still to run)

The pack d2d is the old fork lineage: `debug players` has 7 columns and `debug warps` 4. The bot's parsers accept 7, 8 and 9 columns (#658) and 4 or 8 for warps: with 4 columns `HasClick` stays false and the push click goes to the tile as before, which entered the Den on that lineage (docs/probes/warpclick-2026-11-14.md, the iv1 run). No d2d change is needed unless the 20 minute run shows bounces at entrances.
