# Automatic Allocate Skills (mechanics)

> status: built 2026-11-21 (agent autoalloc), knob `agency.autoAlloc` default 0 (off); not run live. The design, the respec and the currency proposal are in [design/autoalloc-and-currencies-2026-11-21.md](design/autoalloc-and-currencies-2026-11-21.md). Tags: V verified by a test named here, U not.

- Choose a build on the Points page (`GET/POST /api/hero/build`); the choice locks (stored in `<hero>.points.json`: `build`, `locked`, `lockedAtLevel`, `respecs`). Another build is refused while locked (`locked`, 409); the lock ends only with a paid respec (not built: the pay button says "coming soon"). V `TestSetBuildLocksAndRefusesSwitch`, `TestBuildAPITwoClasses`.
- With the knob on and a lock, `Desk.AutoAllocOnce` (a 3 s loop in `cmd/d2bot/autoallocwire.go`) spends one point per tick from the build's next row through the Points desk (legality, verb, read-back), at a calm moment. A skill the hero cannot use yet is held with a reason, never spent silently. Trace: `auto-alloc: clvl N -> skill X (build B)`. V `TestAutoAllocFollowsBuildTwoClasses`, `TestAutoAllocHoldsUnsupportedAttackAndSpendsNext`, `TestAutoAllocStatThenSkill`; the plan itself `TestAutoAllocPlanFollowsRowsTwoClasses` (leveler).
- While locked and on, the leveler's own spending is closed (`Desk.Locked`), so nothing double-spends. Manual `+` presses stay allowed; the allocator plans around them.
- Respec price knobs `respec.*` (placeholders) and the model `points.RespecPrice` (V `TestRespecPrice`); the live price line is on the Points card.
- Scenarios (tools/provingground/scenarios/autoalloc.json): `points.autoalloc-follows-build` (Paladin, `paladin-normal30-v2`), `points.autoalloc-follows-build-sorc-fire` (Sorceress, `sorceress_fire_normal30`), `points.autoalloc-refuses-locked-switch`. They are CHEATED-setup mechanics runs; not run yet (see the card result).
- What `autopilot` means: `Nec.points.json` `autopilot` is the old Points-desk switch for the leveler's own decisions (resource.pointsDecisions); it is false when the player chose a build and has nothing to do with the allocator, which runs from `locked` plus the knob. Banked points: none are banked while a build is locked; every point is spent, only slowly.
- Why it looked idle (user report 2026-11-23, necromancer clvl 4, V from the test bed log, read only): the allocator does spend, but only at a calm moment (a 3 s tick, nothing spent while a fight is on) and it took the 15 stat points first (10 Energy from the old table rows 2-3, then Vitality), so the first skill (Skeleton Mastery) landed about 2 minutes after the lock. Fixed: skills are planned before stats (`skillsFirst`), the summoner table is Vitality-first (3 Energy at clvl 2, SME answers 2026-11-22 section 5), and the Points page shows `Spent by the build so far`, `Unspent now: N stat, M skill` and `Waiting: a fight is on...` (`BuildView.unspent/spent/waiting`). Held skills keep their reason line.
- Proving Ground: `points.autoalloc-necro-clvl4` (autoalloc.json) is the necromancer clvl 4 case; not run on the builder yet (U), see the card result.
- Horizon handoff (allochandoff): a locked table such as `necromancer_summoner_normal30` ends at level 30. The catalogue (`internal/plandata/build-catalog.json`) lists the later tables of the same build with `fromLevel`; once the hero's clvl reaches the next SUPPORTED one (or the followed table has no step left for unspent points: then the nearest later one, early), the allocator follows it. Never an experimental table, never silently: trace `auto-alloc: handoff normal30 -> endgame90 at clvl N`, stored in `<hero>.points.json` (`plan`, `planAtLevel`, cleared by a respec), and the Points page line (`BuildView.plan`: "Plan: Necromancer Summoner, now following the full plan from level 30."). With no supported later table the line says so ("not supported yet, so points stop at the end of this table", or "no plan past level 30"). V tests `TestAutoAllocHandoffTwoClasses`, `TestAutoAllocNoHandoffIntoExperimental`, `TestAutoAllocHandoffWhenTableExhausted` (points, Necromancer + Paladin). Scenario `points.autoalloc-handoff` (level 30 Necromancer): see the card result.
- Builds with no supported plan today (`BuildView.noPlan`, `points.PlanStatus`, V `TestEveryCatalogueBuildHasAPlanOrAReason`): the default table is experimental because the capability table has no rule for an attack/summon skill. sorceress_lightning (Lightning, Chain Lightning; `fallback-lightning` and `primary-blizzard` are also not loaded by the bot), necromancer_poison_nova (Poison Nova, Poison Explosion, Poison Dagger), barbarian_frenzy (Double Throw), druid_tornado (Tornado). Cheapest fix per build: a row for that skill in `capabilities.json` once the fighter casts it (no code in the allocator); for Lightning also load the missing v1 table.
