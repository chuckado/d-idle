## Summary

- **Life and mana from level, class, Vitality, Energy (S, equal in d2d):** a level adds CharStats `LifePerLevel` / `StaminaPerLevel` / `ManaPerLevel` (quarter points, record +0x43 / +0x44 / +0x45) x 64 in 256ths to the stored max and current (FUN_00570880), then life is filled only if it was above 0, mana and stamina always. A stat point adds the per-point byte x 0x40 (op 8 / 9 of FUN_00626200, +0x46 / +0x47 / +0x48), but only the attribute *above the character's own value* is added at read time; the own points' share is inside the saved max. d2d does the same; its only difference is a **truncation of the gear share** (D3).
- **Regen (S, equal):** no natural life regen; `life += hpregen (stat 74)` a frame with a floor of 1 life for a player (FUN_00580610); mana `max(max/ (ManaRegen x 25), 1)` x (100 + stat 27) / 100 + stat 26 a frame (FUN_005806f0, already SKMANA). d2d equal.
- **Defence, block, resistances (S):** defence FUN_006223f0 = stat 31 + dex / 4 (+ skill_armor_percent, order U); to hit and block rolls use it in FUN_0057d9b0 / FUN_0057dd60; block FUN_00622720 = `(stat 20 + BlockFactor) x (dex - 15) / (clvl x 2)`, shield needed, at most 75, a third while running; resistance FUN_0057be00 = `stat - pierce`, a player adds the difficulty penalty to all but physical and magic, clamp `[-100, min(75 + max-stat, 95)]`. These functions were only ever **hooked** (fed a value) by our emulator scripts (`mon_missile.py`, `monster_hit.py`, `sk_melee*.py` hook 0x622720 / 0x6223f0), never run natively: a differential is buildable (section 6) but was not run.
- **Stats 17 / 18 / 21 / 22 (S):** d2d has no player unit stat above id 15; its fight code sums the item props itself; the fork's `dump stats` adds `gear` sums only for ids 16..25 (docs/forkdbg.md). The bot reads 19, 21, 22, 25 from them (d2dsrc/gearstats.go) and not 17 / 18.
- **Findings:** 8 d2d deviations (D1..D8, none proven by a run, tags S / I / U), 4 bot findings (B1..B4). B1 and B2 are code-level facts (S): the bot applies the difficulty resist penalty twice on d2d, and reads the dump's `bonus` list in a different order and length than d2d writes it.
- **PR candidate:** none (no differential run; rule 4 of the decomp lane).
