## Game side, re-derived (V read, then V run)

- **FUN_0056f7f0** (`0x56f7f0..0x56fae4`): the do is `[0x7322b0 + srvdofunc * 4]` (`0x56f953`), its return stored at `[ebp-0xc]` (`0x56f96a`). `srvmissile` (`[ebx+0x46]`) negative jumps to `0x56fa3d`; there `[ebp-0xc] == 0` goes to `0x56f8b3` (return 0). Only past that: `[ebp+0x10]` (the pay argument) and, for a player or monster (`[ebp-0x14]`), a skill with no start function (`[0x732140 + srvstfunc * 4] == 0`) calls FUN_0056bfe0 at `0x56fa7a`. So for a no-missile skill a zero do return skips the payment, FUN_0056c3f0 (`0x56fa8e`) and the delay (FUN_00646ca0 / FUN_0056ef90). Teleport's row: srvstfunc 0, srvdofunc 27, srvmissile -1 (V run, read from the booted Skills.txt record).
- **Callers:** all eight calls of FUN_0056f7f0 were listed (`0x539747`, `0x56fc92`, `0x56fd34`, `0x56fe0d`, `0x56fee2`, `0x56ffb4`, `0x5bf5bc`, `0x5fdc2f`); the six read push pay = 1 (V read). ## d2d side and the claim (V read)

- d2d before: `cast_missile` → `owe()` (Teleport has no srvstfunc, so it is owed) → on the SC action frame `settle_cast()` → `pay()` → `spot()`; every refusal in `spot()` `break`s and the cost stays paid. That is the only difference in order that matters: game.exe pays after the do and only on a landing; d2d paid before and always. For a landing both pay once.
- The claim gives back `last_paid` when the skill's srvdofunc is Teleport and `spot()` did not set `reassigned` (saved and restored around the call, so an earlier `reassigned` in the same tick is kept). Charges: `pay()` sets `last_paid = 0` for a charged cast, so a refused charged Teleport still uses its charge in d2d; whether FUN_0056bfe0 is where game.exe uses the charge is U (not claimed; required change B3).
- The delay: game.exe also skips the delay on a refusal (`0x56fa93..0x56fad6` is past the exit); d2d still calls `start_delay`. Teleport has no delay (I), so nothing differs.
