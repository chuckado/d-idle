## 5. Standing process (so nothing is lost again)

**(a) Briefs and results.** Every `d2-decomp` brief gets a mandatory section `UPSTREAM NEXT STEPS`: (1) the d2d side differential exists or not, (2) the pipeline stage reached (S0 to S1), (3) a row appended to section 1b of this file (id, topic, source, evidence, oracle path, next stage, date), (4) a drafted issue for a game-side-only finding. A decomp result without that row is not closed (the coordinator rejects it at merge). Each row carries `last: YYYY-MM-DD`. Minimal staleness tool, proposed (not written: it is outside this card's `owns:`), `tools/upstream/pipeline_stale.py`: read the section 1b table, parse the `last:` date and the stage, print every row older than N days (default 7) that is not merged or closed:

```python
import re, sys, datetime, pathlib
doc = pathlib.Path("docs/upstream/pipeline-2026-11-14.md").read_text()
limit = int(sys.argv[1]) if len(sys.argv) > 1 else 7
today = datetime.date.today()
for line in doc.splitlines():
    m = re.search(r"^\| \d+ \| (P\d+) .*last: (\d{4}-\d\d-\d\d)", line)
    if m and (today - datetime.date.fromisoformat(m.group(2))).days > limit:
        print(m.group(1), "stale since", m.group(2))
```

(`last:` is added to the Blockers cell of each 1b row by whoever touches it.) A pipeline staleness line goes into the coordinator's STATUS review.

**(b) Fork rebase lineage.** `docs/fork-rebase-*.md` carries a table "carried patch -> pipeline row": every non-private patch (today: `75891650`, `060c8901`, `c3e24fcb` -> P02; `fork-only/sandbox-swing` `2e58bdc6` -> P01) names its row; the rebase step drops each whose row is in 1a (a `git cherry` / `git log upstream/main --grep` check is the gate). Private-only patches (section 6) are marked `PRIVATE` and never get a row.

**(c) Review step.** Per session (and at least weekly) the coordinator runs: `gh pr list -R psi29a/d2decomped --author shatteredeagle --state open`, `python3 tools/upstream/pipeline_stale.py 7`, `git log upstream/main --since=7.days` against the section 1b "upstream state" cells, and checks the slot count (3). Proposed text for the ops repo's `docs/dispatcher.md` (not mine to edit):

> **Upstream pipeline review (every session, at least weekly).** Open `docs/upstream/pipeline-2026-11-14.md`. (1) Run the staleness script, 7 days. (2) For each row at S2 or later: is a slot free (3 open PRs)? Is the verifier done? Ask the user for the push go on the next ready batch (standing go since 2026-11-07). (3) `git log upstream/main --since=7.days`: any row now fixed upstream moves to 1a. (4) Any decomp or probe result of the last week without a pipeline row is a defect: send it back. (5) Wave: if fewer than 3 PRs are open and a candidate is at S1, launch the fork-patch agent from `docs/upstream/briefs/`.

## 6. What stays private, and why

Lockstep (`--lockstep`, `--time-scale`, frame stepping), the lab verbs (`--lab-verbs` setup and cheat verbs: `debug act/hit/merc/give/spawn/quest ...`), the item verbs (`--item-verbs`; upstream's issue #83 asks for a play bot that works "by clicks only", so a verb that places items directly runs against that goal), framefeed and `cursor on|off` (viewer streaming), the devctl lab extensions, the table overlay's lab use, and the icon and Steam art (fork-only branding). Reasons: (1) they are instrumentation or cheats for our measured runs (AGENTS.md "crutch rule", ADR 0014), the maintainer's project is a reimplementation checked against game.exe, and a cheat verb has no place in it; (2) the user decided "lockstep patches stay in the downstream fork until upstream wants them" (docs/decisions.md, ADR 0010 addendum) and ADR 0003 (fork published as a public GPL fork, source offered with the build); (3) every flag-gated verb is off by default and absent from the friends release, so keeping them in the fork loses nothing upstream needs. The fork lineage is published as a public GPL-3.0-or-later fork; nothing here changes that. No patch text enters this repo (GPL, docs/decisions.md).
