## The decomp, re-read (V read, capstone over game.exe sha256 `631066c1...`)

- **Flag chain, `FUN_0057cee0` `0x57d2e4..0x57d3c3`.** Flag 2 -> `FUN_00580a70` mode 0, return; else flag 8 (`test al, 8` at `0x57d332`) -> `push 0x13` (`0x57d350`), `call 0x580a70` (`0x57d356`), **return** (`0x57d361`); else flag 4 -> `FUN_005809d0` mode 4. A knocking hit never also tries the get-hit, refused or not.
- **`FUN_00580a70`.** `0x580adc call 0x57edd0; test eax, eax; je 0x580b63` (the epilogue: nothing set, no used skill stored, no mode function called). Then, because its fifth argument is 0 on the knock call (`push 0` at `0x57d34c`), **`0x580af6 call 0x57eec0`** (the used-skill gate, P04's function) with new mode 0x13, and `je 0x580b63` again. The brief and the trace name only the first gate (finding 2).
- **`FUN_0057edd0` (`0x57edd0..0x57ee6f`).** Reads only `unit+0x60` (with `FUN_0063c1e0`), the new mode (EBX), the current mode `unit+0x10`, the class `unit+4`, the queued end event (`FUN_0057ed70`: `FUN_005415a0(1) + 5 >= game+0xa8`) and, for SQ only, the used skill (`FUN_0057ed90`). New mode 0x13 > 0x11 -> `0x57ee08`, the current-mode table (`0x57eea8` index, `0x57ee8c` targets), decoded again: DT, GH, BL, DD -> `0x57edf0` (refused, no other read); NU WL RN TN TW S2 S4 -> `0x57ee68` (allowed); A1 A2 SC TH -> `0x57ee1e` (allowed only while the end event is queued: new mode is not 4 or 9); KK -> `0x57ee38` (the queued test); S1 refused for class 0, S3 for class 5; SQ -> `FUN_0057ed90`; current mode above 0x12 (the knockback 0x13 itself) -> allowed (`0x57ee0b`). The trace and the claim comment are right.
- **The `+0x60` branch** (`0x57edd3..0x57edf4`): with `unit+0x60` set and `FUN_0063c1e0` true, every new mode except 0 and 0x11 is refused, 0x13 included. A player holding a cursor item is never knocked back in game.exe; d2d does not model it. It only refuses more, so it cannot turn the GH cell around; the harness's `+0x60 = 0` is a fair stand-in for a player with an empty cursor (finding 5).
- **Damage is not part of the refusal.** Every caller of `FUN_0057cee0` (25 call sites, xref scan of `.text`) calls the damage function `FUN_0057c6c0` just before it (`0x5ad8c6`/`0x5ad8d3`, `0x56ba73`/`0x56ba7f`, `0x57d5c7`/`0x57d658`, ...): life is taken first, the mode answer comes after, so a refused knock still damages. d2d's claim changes only the knock block's condition; the damage, Crushing Blow, poison, chill, stun, curse and mana-burn lines below it run unchanged (V read, `tick.cpp` `hurt_side`). The answer to brief question (2): yes, only the mode change is refused, in both.

## d2d side, read (V read, r2)

- The player enters GH in exactly two places, both in `hurt_side`: the knock block (sets `knock`) and the big-hit block (resets `knock`), `tick.cpp:681` and `:738` (grep of `kModeGH` over `components/`). So "GH with `knock` unset" is exactly a real get-hit; Leap's landing knocks monsters back (`land(..., blow.knockback)`), never the player; the merc's knock is `knock_back(*actor->merc, ...)`, a monster path. Nothing else reaches GH with `knock` unset.
- A refused knock in GH moves nothing: the knock block is skipped whole (no `knock`, no `set_pmode`, no `pmode_until`); the slide code above it only moves the player when `knock` is set; the big-hit block refuses on `get_hit_running`; the struck-cue branch requires `pmode != GH`. The claim's unit assert checks hold, `knock` and `x`.
- **Knock and big hit in one call.** `Foe` aggregates every hit on the player in one tick. From GH, the knock is refused and `get_hit_running` refuses the get-hit: nothing changes, as game.exe's flag chain does for a knocking hit (refused, return) and for a big hit (refused). Right for this cell, but the unit test only uses a 1-point knock, so this case is not pinned (finding 4). From other modes the one-call order question (game.exe processes the two hits one after the other) is unchanged by the claim and outside it.
- **Knock with no room.** The claim's cell refuses before room matters, in both programs (`0x580adc` precedes the mode function, which builds the path; d2d's new condition precedes `unit_blocked`). Not relevant to the claim. Elsewhere (NU, no room) d2d starts no knock and then may give a get-hit; game.exe returns after flag 8. Pre-existing, U, outside the claim; the test's `World` has no level, so no-room is never exercised.
