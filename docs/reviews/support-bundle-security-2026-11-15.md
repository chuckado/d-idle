# Security review: support bundle upload (branch agent/support, tip 88eecae7b)

> status: review of task 542 / card `support` before merge (mergeq #811). Reviewer: Opus, single, offline. Nothing deployed, nothing uploaded, no game.

Tags: **V** = read in the repo at 88eecae7b or run (how is said), **S** = reasoned, **U** = not checked. PoC inputs were run through `support.Redact` / `support.Scan` / `support.Build` in a throwaway `_test.go` in the review worktree (deleted, not committed). Package tests pass: `go test -p 1 -count=1 ./internal/support/ ./cmd/d2supportrecv/` and `go test -p 1 -run Support ./internal/watch/` (V, run on the small box, per package).

## Verdict

**Ship after fixes.** No blocker: the design is sound (allowlist with fixed entry names, Send takes an id not content, write-only hashed token, receiver never unpacks, fetch script re-checks). But the redaction misses several classes the threat model promises, the fail-closed scan cannot catch them because it shares the rule table, the stated backstop (the preview) shows only 40 log lines, and the most important secrets (watch token, view token, upload token, home directory) are not fed to the literal scrubber. Fix M1 to M4 before the first friend pack carries `SUPPORT_TOKEN`; the minors can follow.

## Major

### M1. Redaction misses whole classes, and Scan cannot see what Redact missed (V, PoC)
`internal/support/redact.go:19-47`; the scan reuses the same `rules` (`scan.go:128`), so each gap below gives `findings=0` and the bundle is sendable. Failing inputs (input -> output of `Redact`, `Scan` finds nothing):

Recommendation: (a) secret values: after a secret name, redact to end of line (or to the closing quote), not to the first space; add `pass`, `pwd`, `pw` as whole-word names and allow whitespace as a separator after `key`/`cdkey`; (b) run the JSON pass with `enc.SetEscapeHTML(false)` and redact every JSON *string value* before marshalling (walk the tree, `Redact` each string), so escaping never hides a shape; (c) homepath: accept `\\`, `/`, `\` separators and `Z:\home\`, and redact to the next separator including spaces; (d) IPv6: use `net.ParseIP` on `[0-9a-fA-F:.]{2,}` candidates containing `::` or 2+ colons; (e) hex: keep 40-hex only when it equals `buildinfo` commit, not every 40-hex; (f) token: drop the "needs a digit" condition for 32+ runs that also contain `_` or `-` or mixed case; (g) add a test row for each input above to `support_test.go`.

### M2. The known secrets are not given to the literal scrubber (V, `cmd/d2bot/supportwire.go:53-59`)
`Extra` holds the container host name, `$USER`, the layout root and the state dir. It does not hold the values the threat model names first: the watch token (`resolveWatchToken`, `cmd/d2bot/ladder.go:407`), `D2DVIEW_TOKEN` (read at `supportwire.go:186`), `D2BOT_SUPPORT_TOKEN`, `$HOME`/`os.UserHomeDir()`, `user.Current().Username` (`$USER` is often unset in containers and under service managers), and the host names of `D2BOT_WATCH_ORIGIN`, `D2BOT_SUPPORT_URL` and `D2BOT_UPDATE_FEED`. Literals are the only rule that does not depend on shape, and Scan already blocks on them (`scan.go:123`). Failing input: a watch token without a digit (M1 row) printed in any log line goes out. Recommendation: add those values (and their JSON-escaped and backslash forms for paths) to `Extra`; for tokens, do it even when the scan would catch them, and add a `supportwire_test.go` case that seeds a digit-free 32-char watch token.

### M3. The preview is not the backstop the threat model relies on (V, `internal/support/bundle.go:142`, `internal/watch/web/supportui.js:123-125`)
`docs/support-bundle.md` says the person "sees exactly what would be sent" and, for secret shapes no rule knows, "that is why the preview shows the log excerpt". The sheet shows file names, sizes and the last 40 lines of `log.txt` (up to 1 MB after redaction). `errors.txt`, the four viewer JSON files, `knobs.json`, `decisions.json`, `deaths.json` and all earlier log lines are never shown before Send. The zip sent is the one built (Send takes the id, `supportapi.go:383`), so "same bytes" holds; "seen bytes" does not. Recommendation: add a "Show everything" view (per file, the redacted text the zip holds, paginated) and link it from the sheet, or make Send available only after the person opened it; until then reword the doc ("shows the file list and the end of the log") and drop "independent" from threat-model item 1 (the scan is explicitly not independent, see "Redaction and the fail-closed scan").

### M4. nginx buffers unauthenticated bodies; the per-address limit collapses to one bucket without the CF header (V by read, S on impact)
`cmd/d2supportrecv/nginx-support.conf:5-8` and `Dockerfile:12`, `recv.go:134-148`.
- `proxy_request_buffering on` with `client_max_body_size 21m`: nginx reads and spools the whole 21 MB body to its temp dir **before** the receiver sees the request, so the receiver's "auth and rate limit before the body" never protects nginx. Failing input: `curl -X POST -H 'Content-Type: application/zip' --data-binary @21MB.bin https://<updates host>/support/upload` in parallel from a few addresses, no token: nginx disk and bandwidth are spent for each, the receiver answers 401 after. The doc's "size cap enforced before buffering" is not true at the edge.
- The image always runs `-trust-proxy`; nginx copies the client's own `CF-Connecting-IP` (`$http_cf_connecting_ip`) and clears `X-Forwarded-For`. Through the Cloudflare tunnel that header is set by the edge (fine). On any path that bypasses the tunnel (LAN, a port forward, a misrouted vhost) a client can set `CF-Connecting-IP` to a fresh value per request (per-address and failed-login limits bypassed), and a request without it falls back to `RemoteAddr` = the nginx container, so **all** clients share one `-ip-rate 10` bucket: 10 garbage POSTs an hour stop every friend's upload (429).
Recommendation: `proxy_request_buffering off` (the receiver reads at most 20 MB through `MaxBytesReader` after auth) plus an nginx `limit_req zone` on the location and a guard that answers 401 at nginx when the Authorization header does not start with the bearer scheme; in the receiver, with `-trust-proxy` and no `CF-Connecting-IP`, refuse (or bucket by a fixed "unknown" key with its own low limit) instead of using the proxy address; document that the location must only be reachable through the tunnel (or use `set_real_ip_from`/`real_ip_header` with the Cloudflare ranges).

## Minor

- **m1. One shared pack token lets any holder evict real bundles** (S; `recv.go:306-340`, README step 1 names the line `pack`). The token ships in every friend pack (a file that gets forwarded). A holder can send 20 x 20 MB per hour from rotating addresses; `-quota-mb 2048` purges oldest first, so in about five hours every real bundle is gone. Recommendation: one token per friend (label = friend), a per-token share of the quota, and never purge files younger than 24 h (refuse with 507 instead).
- **m2. Support POST routes work without a token when the watch token is empty** (V; `http_answer.go:124`, `ladder.go:420` "loopback only"). Any local process (or a container on the host network) can POST `/api/support/bundle` then `/api/support/send` with no press of Send; Origin is only checked when present. Low impact (the bundle goes to the owner), but it contradicts threat-model item 2. Recommendation: `SendHandler` refuses when `o.Token == ""` unless an allowed `Origin` is present.
- **m3. Double Send of one id uploads twice** (V; `supportapi.go:383-402`: `get` happens before `a.build.Lock()`, delete after). Two quick presses or two tabs send the same zip twice, burning the token's hourly budget. Recommendation: mark the bundle "sending" under `a.mu` before releasing it.
- **m4. leakcheck exception is the whole file and the file holds the owner's real update host** (V; `docs/process/leakcheck-allow.txt:12`, `internal/support/support_test.go:24` seeds `updates.<owner domain>`; `redact.go:45` hard-codes the owner's domain word split in two to pass the scanner). The domain word is already public through `cmd/leakcheck`, so this adds a full host name rather than a new secret. Recommendation: seed `updates.example-owner.test`, take the owner's host names at run time from `D2BOT_SUPPORT_URL`/`D2BOT_UPDATE_FEED` (M2) instead of a code literal, and drop the path exception (or narrow it to a per-line marker).
- **m5. README contradicts itself on clear-text tokens** (V; `cmd/d2supportrecv/README.md:5,21`): "a token is never stored in clear" but step 1 `tee`s it into a root-owned file on the server. Recommendation: pipe straight into the pack file on the owner's machine, or say where the clear copy lives and that it is 0600.
- **m6. Live checklist rate test cannot pass as written** (V; `docs/support-bundle.md` checklist "send 21 times"): `-ip-rate 10` answers 429 at the 11th request from one address, before `-token-rate 20`. Recommendation: say "11 times from one address, or 21 from several".
- **m7. support-fetch.sh writes the unpacked bundle with the default umask** (V; `d2lod-ops/tools/support-fetch.sh:26-27`). A ticked character save and the logs land group/world-readable under `$HOME/support`. Recommendation: `umask 077` at the top. Also: log text from a token holder can carry terminal escape sequences; view with `less` (not `cat`).
- **m8. Receiver memory and panic logging** (S; `recv.go:206`, `main.go:45`). Up to N concurrent authorized 20 MB bodies are held in memory (no concurrency cap; only token holders reach it). `net/http` logs "http: panic serving <remote addr>" on a handler panic, contrary to "logs no address". Recommendation: a semaphore of 2-4 uploads and `ErrorLog: log.New(io.Discard, "", 0)`.
- **m9. Scan cost** (V; `scan.go:123-125`, `ctx` calls `Redact`): `literalRx` compiles a regexp per line per literal, on up to 4 MB of log, while holding the build lock. No correctness issue (RE2 is linear, no timeout path exists so nothing can "fail open"); compile once per Build.

## What holds (checked)

- Allowlist and entry names (V, `bundle.go:102-138`): the zip is written from memory with fixed names (`Allowed` keys, `MANIFEST.txt`, `screenshot.png`, `save/characterN.d2s`); a collector name cannot reach the zip, so no traversal, symlink or directory entry is possible from the client. The client never unpacks anything (no client-side zip bomb surface).
- Fail closed (V): any finding returns before the zip is built (`bundle.go:145`); `Sendable` needs no findings and a zip (`bundle.go:80`); Send answers 409, download 404 without a zip. Invalid JSON is replaced by a placeholder, not passed through. `Scan` is a pure function with no error or timeout path; there is no way for it to "fail open".
- `.d2s` without the tick (V): `save/` inputs are dropped unless `IncludeSave`; a save header outside `save/` is a finding; the save file name never carries the character name.
- Environment (V): no env dump; only `D2BOT_IMAGE_TAG`, `USER`, `D2DVIEW_TOKEN` (sent only to the tap) and the two support values are read.
- Screenshot (S): only with the tick, magic-checked, from the d2d tap's own encoder (no camera EXIF); not text-scanned. Acceptable as opt-in; the sheet should say it shows the character name.
- Upload URL and token (V): never in the preview, `/api/support` (only `configured`), glance or errors (fixed words; `fmt.Errorf("... answered %d")` carries only the status); https required (`send.go:39`); redirects not followed (`send.go:69`).
- CSRF and DNS rebinding (V by read, `policysheet.go:733-770`): a browser always sends `Origin` on a POST; an origin outside the list gets 403, JSON-only forces a preflight, the token is required when set; a rebinding page has its own origin and is refused. Download needs the 64-bit random id that only the POST answer carries.
- Receiver (V): SHA-256 hashed tokens with `ConstantTimeCompare`; no read, list or code-lookup route (codes are not a path input anywhere); rate and auth before the body; `Content-Length` check plus `MaxBytesReader`; zip magic, central directory, 64 entries, no `..`/absolute/backslash/dir/symlink names, 100 MB declared size; random code from a fixed alphabet, `O_EXCL`, 0600; error replies are fixed words; only the start line is logged; server timeouts set.
- support-fetch.sh (V): the code is anchored-regex checked before it reaches `scp` (no injection), names are re-checked in Python, `zipfile.extractall` sanitizes paths and writes no symlinks, and `ZipExtFile` stops at the declared size with a CRC check (a lying size cannot bomb the owner's disk).

## Recommended order
1. M2 (literal secrets: an hour, closes the worst case). 2. M1 rows + tests. 3. M4 nginx/receiver. 4. M3 "show everything" or the doc wording. 5. Minors with the next receiver change.

## Re-verification of the fixes (tip 8981d1f8e, merged into this branch)

Done independently: the builder's report was not used as evidence. Every input from M1 was run again through `Redact`, through the new `Scan` on the **raw** input (to test that it is independent) and through `Scan` on the redacted text. JSON cases went through `Build` and the zip bytes were read back. A throwaway `_test.go` was used and deleted. The package tests pass (`go test -p 1 -count=1 ./internal/support/ ./cmd/d2supportrecv/`, `-run Support ./internal/watch/`, V).

**M1, fixed (V).** All 16 inputs are now redacted (`passphrase: "<secret>"`, `<home>` for JSON, slog, Wine Z: and URL-encoded paths, `<ip6>` for compressed IPv6, `<host>` for single-label URL hosts and public suffixes, `<hex>` for 40-hex, `<token>` for the digit-free and 31-char tokens, `<cdkey>`/`key <secret>`). In the zip, `&t=` and `&sig=` inside JSON come out as `<token>`, and `C:\\Users\\alice` as `<home>\\AppData`. Scan now has its own pattern set (`scan.go:32-69`) and catches 13 of the 16 raw inputs with no redaction at all, so it is a real second line now. Shapes that still pass both (low; M2 literals cover the important case): a bare PC name outside a URL (`connected to alice-pc`), a 34-char mixed-case token with no digit and no symbol (about 0.1 % of base64url watch tokens, but the watch token is now a literal), and MAC addresses. A camelCase secret key in JSON (`{"wifiPass":"hunter2 x"}`) is not redacted, but Scan blocks it (`secret-assignment`): fail closed works.

**M2, fixed (V, `cmd/d2bot/supportwire.go` `knownLiterals`).** Literals now include the watch token and the API token (passed from `ladder.go`), `D2DVIEW_TOKEN`, `D2BOT_SUPPORT_TOKEN`, `HOME`, `os.UserHomeDir`, `USER`/`LOGNAME`/`USERNAME`, `user.Current()`, the host name, and the hosts and paths of `D2BOT_SUPPORT_URL`, `D2BOT_UPDATE_FEED`, `D2BOT_WATCH_ORIGIN` and `D2BOT_WATCH_TAP_URL`, plus the data dirs. Each is also added in its JSON and forward-slash forms (`NewLiterals`). Strings shorter than 3 characters are skipped, which is fine.

**M3, fixed (V).** Every text file in the zip (`Allowed` files and `MANIFEST.txt`) gets an excerpt in the preview plus "Read it all". That button pages `b.text[name]`, which is stored after the 1 MB cut (`bundle.go:130-135`), so it is exactly the bytes in the zip. Send still takes the id of the remembered bundle. A second press while the upload runs is refused (`sending` map). The screenshot and save are binary and shown only by name; that is acceptable because both are opt-in with their own ticks.

**M4, mostly fixed (V by read; deployment topology U).**
- nginx: inside `location = /support/upload`, the `if` lines answer 401 when the bearer is missing or malformed and 400 when the CF header is missing. Both run in the rewrite phase, before nginx reads the body. `proxy_request_buffering off` and a 16k body buffer mean no 21 MB spool. `limit_req` is keyed on the CF header.
- Receiver: with `-trust-proxy` and no valid `CF-Connecting-IP` it answers 400. A request is no longer counted under the proxy's own address. There is now a concurrency cap (`max-busy` 3), a 24 h minimum age before a bundle can be purged (a full inbox answers 507), the panic log is silenced and tokens can be labelled per friend.
- A friend coming through the Cloudflare tunnel always carries the header (the edge sets it), so they are not refused for lack of it.
- The header can still be forged by anyone who reaches nginx without going through the tunnel. The receiver cannot tell the difference; only the nginx config can. Recommendation: add `allow <cloudflared container address>; deny all;` to the location (or `set_real_ip_from` that address with `real_ip_header CF-Connecting-IP`), so the header is trusted only from the tunnel.

**R1, new, major for availability (V by read, `recv.go:184-195`).** The global counter (`-global-rate` 200 per hour) is incremented **before** the per-address limit and before authentication. nginx allows one CF address 6 requests per minute (360 per hour). So a single unauthenticated client coming through the real tunnel, without forging anything, can send about 200 garbage POSTs with a well-formed but wrong bearer in about 35 minutes. Every friend then gets 429 for the rest of the hour. Fix: check the per-address limit first, and count the global limit only after `tokenOK` succeeds (put failed logins in a separate global fail bucket that never blocks authenticated uploads). Add a test: 250 unauthenticated requests from different addresses, then one valid upload still returns 200. Friends keep "Save to file instead", so no data is lost.

**m1-m9 (V).** Per-friend labels and the min-age purge (m1). Send and build refuse a missing origin when no token is set (m2). The double send is guarded (m3). The README and checklist were corrected (m5, m6; not re-read line by line). The max-busy cap and the silent ErrorLog (m8). Literals are compiled once per build (m9). m7 (umask in support-fetch.sh, ops repo) was not part of this tip: U.

**Leakcheck exception (V).** The owner's domain is gone from `internal/support` (0 hits); the test seeds `updates.example-owner.test`. The whole-file `path internal/support/support_test.go` line is still needed: without it the file has 15 synthetic hits, all example values. The one new allow entry (an nginx header variable name) is narrow. Acceptable.

### Final verdict

**Ship the client side** (bundle, redaction, scan, preview, send): every confidentiality finding is fixed and re-verified. **Receiver: one more fix before it is deployed.** Make R1 (the global-limit order) and add the nginx source restriction so the CF header is trusted only from the tunnel. Both are small changes; neither is a confidentiality issue.

## Merge note (2026-11-16)
