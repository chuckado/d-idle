# Druid fire: what the engine plays, and what a later card must build

> status: current (card druid1, 2026-11-20; Fable roadmap Q8, class 5 after the Sorceress fire build, the Necromancer summoner, the Hammerdin and the Barbarian Frenzy). Design note, no combat code. Evidence tags: V verified (how said), S read in code or docs, U unverified. Sources: `internal/combat/druid.go`, `fighter.go`, `classdata/profiles.json` and `skills.json`, `docs/classes/druid.md`, `docs/sme/class-druid.md`, `docs/design/fable-review-2026-11-19/03-classes-plan.md` section 3.5 and `02-fidelity-and-gaps.md` A8, the patched skills.txt of the worker host (requirements, mana, delay, `srvdofunc`, `range`: V, read with `cmd/mpqcat` on the builder).

## 1. Finding: which build, and what exists

The review's D1 (Fire, Normal: Firestorm, Molten Boulder, Fissure) is the community's Normal opener and the first Druid build in the roadmap row "Sorceress Blizzard, Druid Fire". The file is `druid_fire_guide`. D2 Wind (Tornado, Hurricane, Cyclone Armor) is the Hell build but needs an aim rule for an erratic missile and d2d has no verdict on its flight (A8); D3 summoner is slow; shapeshifters are "never for the bot" (K14). Those stay unsupported rows.

The default Druid already plays this line: table `druid_fire_normal30` (Firestorm, Molten Boulder, Eruption = Fissure from clvl 12; V `docs/plan/data/`), profile `druid` (Eruption from 12, Cyclone Armor in the buff ladder) and `druid.go` upkeep for summons. No Druid skill has ever been cast in a live game (U: `docs/classes/` has smoke notes for three other classes, none for the Druid). What was missing: a table written as a build file, a named profile, capability rows for all 30 skills, and a Proving Ground check.

Correction to the brief's list of ground-targeted skills: skills.txt (V) makes only Firestorm (`srvdofunc` 117), Molten Boulder, Fissure/Eruption (28) and Volcano (123) point-aimed fire spells. Armageddon (124), Hurricane (124) and Cyclone Armor (18) are cast on the caster and last on a timer; Tornado and Twister (118) are travelling missiles. The rows say so.

## 5. Ground-target delivery: what a later combat card needs, for ALL classes

Scope: every skill whose capability delivery is `ground`, plus the cast-at-a-point skills the table marks `pet` or `projectile` that still need a point. No code is written here; the engine today casts every `ground` skill (`KindGround`, "aimed at the ground under the monster", `skills.go`) at the targeted monster's CURRENT position through `Fighter.cast` (`CastAt` with the bound F-key, or a right-click when the skill sits on the right hand). That is S, read in `fighter.go`; it is the whole implementation.

Rows that use it (capability table, V rows from skills.txt): Sorceress Blizzard, Meteor (experimental) and Inferno, Blaze, Fire Wall, Hydra, Frozen Orb (unsupported); Paladin Blessed Hammer (experimental, also needs K11 standing in the pack) and Fist of the Heavens (unsupported); Necromancer Corpse Explosion (a corpse point, K8), Bone Wall, Bone Prison, Poison Explosion and the curses (a monster point); Druid Firestorm, Molten Boulder, Eruption, Volcano (experimental), Plague Poppy (unsupported); Assassin sentries (`trap.go` has its own placement, K10). Barbarian Find Potion, Find Item and Grim Ward are corpse points (K8 shape).

What the card needs, in order:

1. Aim point selection. Today the point is the monster's position when the tick reads it. A later card needs: a lead for a moving pack (the Blizzard and Meteor delay is 45 frames and 100+ for Volcano, V skills.txt, so the target walks away), a choice between the nearest monster, the centre of the densest cluster (`crowd.go` has a census) and the pack's edge (Blessed Hammer and Fissure want the cast ahead of the pack then a step back, `docs/classes/druid.md` section 8, S), and an offset rule for erratic missiles (Tornado, Twister). The rule is data per skill: add `aim` fields (`target | cluster | lead | offset`) to `classdata/skills.json`, not skill names in Go.
2. Line of sight and reach. `reach.go` has `LineOfSight(a, b)` over the walkability grid; a ground cast must check it from the hero to the aim point (a point behind a wall wastes mana and, for Meteor, drops the spell on the wall), clamp the point to the skill's `range` (skills.json: Blizzard 30, Meteor 30, Fissure 20, Volcano 25, Firestorm 14, Blessed Hammer 9; Kolbot's numbers, U) and walk closer when out of range. No ground skill checks either today (U that the generic path casts through a wall).
3. Cast-on-ground input. The pixel path is a right-click at the screen point of the aim (`screenOf`); the d2d path is `cmd skill <id> X Y [unit] [left]` (V for a unit target in `docs/d2d-backend.md`, U for a ground point: its open question 5 "ground-targeted skills with no unit"). The input layer's capability file (`data/input/caps/*.json`, schema `inputcaps/1`) names verbs; today only `input.select` exists on the devp14 sandbox and the frozen game-exe backend has none. A later card adds a verb name (for example `input.cast-at`) to the caps files, the bot adopts it only when the backend lists it, and the pixel path stays the fallback. The Proving Ground drill must show with `writes after start: 0` that the spell lands at the aimed point.
4. Cooldown and mana. skills.txt `delay` is in frames (25 per second): Firestorm 15, Molten Boulder 50, Eruption 50, Volcano 100, Armageddon 150, Blizzard 45 (V). The engine already skips Blizzard while its delay runs (`docs/combat.md`); the card makes it a table (read `delay` into `SkillSpec`, not the Blizzard special case) so Fissure, Volcano and Meteor use it. Mana: reserve per skill (a Volcano is 25 of a pool of about 60 at clvl 20) with the existing `manaReserve` as the floor; skills with a flat cost (Fissure 15) fall to a cheaper skill when the pool is short.
5. Verification. A fidelity check on d2d for each skill's effect before any claim (A5 skill delay for Blizzard, A8 for the Druid); a live drill per class on a throwaway character; the survival model's danger check (a ground cast leaves the caster standing at the front, docs/classes/druid.md section 6).

Order of value: Eruption and Firestorm (Druid, cheap, the aim is a monster point), then Blizzard and Meteor (Sorceress, the lead and the delay), then Blessed Hammer (needs K11), then the corpse and trap placements, which are different cards (K8, K10).
