# Necromancer summoner: what the engine plays, and what a later card must build

> status: current (card necro1, 2026-11-20; Fable roadmap Q8, class 2 after the Sorceress fire build). Design note, no combat code. Evidence tags: V verified (how said), S read in code or docs, U unverified. Sources: `internal/combat/necro.go`, `necro_corpse.go`, `classdata/profiles.json`, `docs/summon.md`, `docs/classes/necromancer.md`, `docs/design/fable-review-2026-11-19/03-classes-plan.md` section 3.3 (row N1 Summoner), skills.txt of the worker host (reqLevel, prerequisites, mana columns: V).

## 1. Finding: the engine is further than the brief assumed

The brief expected "only melee and Teeth". The combat code already has, for the Necromancer: a summon census (`CountMinions`), summon upkeep (`KeepSummons`, `planSummon`, `castSummon`), corpse search, curses (`Fighter.Curse`), Bone Armor by state, Corpse Explosion (`corpseExplode`) and a Revive branch. V live 2026-10-29 (agent necrolive, docs/summon.md "Live results"): Raise Skeleton from a corpse within 4 subtiles (count 1 to 4, cap equals the skill level), Clay Golem (no corpse), Raise Skeletal Mage census (class 364), Amplify Damage cast at pack members, Bone Armor state 14 and recast by state. Not seen live: Weaken, Lower Resist, Revive, Fire Golem, Corpse Explosion, boss corpses, curse state read-back.

Names are the skills.txt names (`BloodGolem`, `IronGolem`, `FireGolem`), as the shipped plan tables spell them. Each row carries kind, delivery, tier with a reason (required when not supported), element, `reqLevel` and `reqSkills` (V skills.txt), synergies (V skills.txt: `DmgSymPerCalc`/`EDmgSymPerCalc` for damage rows; `Skeleton Mastery` and `Golem Mastery` for summons) and the mana source. Tiers are typed, not generated (ADR 0020 wants them from Proving Ground rows: P2).

## 3. The build: `necromancer_summoner_guide` (experimental, opt-in)

- File of record: `internal/buildfile/testdata/necromancer-summoner-guide.json` (`didle.build/1`); the plan table `internal/plandata/build-necromancer_summoner_guide.json` (copy in `docs/plan/data/`) is its expansion, kept in step by `TestNecromancerSummonerGoalFileMatchesTable` (`UPDATE=1` rewrites the rows). Validated under the capability rules (skills.txt: caps, required levels, prerequisites) and row by row by `buildfile.CheckTable`.
- Why this build: review row N1 ("the safest idle hero there is: the army takes the hits, failure is slow not fatal"). Track: Normal (to about clvl 33) skeletons and mastery, Clay Golem, Amplify Damage, Bone Armor from 14, mages from 12, Corpse Explosion 3; Nightmare Raise Skeleton and mastery to 20, mages 8 to 12, golem mastery, the Weaken, Terror, Decrepify chain; Hell Fire Golem (through Blood and Iron Golem prerequisite points), Revive, Lower Resist (Iron Maiden and Life Tap prerequisites), Summon Resist. Points land late by the table's own arithmetic (Weaken at clvl 50, Fire Golem 74, Revive 75): V from the expansion.
- Selector and combat line: the table's data (`selector`, `combat: summoner`, `tier: experimental`), no Go. Run it with `levelerBuild necromancer_summoner_guide`. The default Necromancer stays `necromancer_summoner_normal30` then `necromancer_summoner_endgame90` (V `TestNecromancerSummonerBuildSelectableAndDefaultsUnchanged`).
- Combat profile `necromancer/summoner` (`profiles.json`): Teeth (one point) then the plain attack, Bone Armor, layout F1 to F8 (Teeth, Raise Skeleton, Raise Skeletal Mage, Clay Golem, Bone Armor, Amplify Damage, Corpse Explosion, Revive). Unknown Necromancer profile or another class asking for `summoner` is an error naming it (V `TestNecromancerSummonerProfile`).
- Planner shadow (`agency.planner` knob, shadow only): a sane plan at every clvl 1 to 30 (archetype summoner, main = the top summon, no unsupported skill in any slot, a build line), the late-game table flags Decrepify, Terror and the golem prerequisite points as unplayed, the summon slot agrees with the profile's keys at seven checkpoints (V `internal/agency` tests). Attack agreement with the profile is 0 of 5 for this table by design (profile Teeth, planner "Attack": pets have no damage in the model; fixture rows say so). Viability is a lower bound: pet damage is not modelled, so even a strong hero is judged against the plain swing (V `TestNecromancerSummonerViability` logs it).

## 4. What a later card must build (nothing of this is implemented here)

| id | need | evidence | size |
|---|---|---|---|
| S1 | A live check of the summon loop on this build: Raise Skeleton, mages, Clay Golem, Bone Armor through a whole Normal act with `writes after start: 0`, count and recast when minions die (the census is a snapshot read, so recast after death is by design but was only seen with a hand-fed corpse) | docs/summon.md "Needs a live check" items 2, 4, 5, 6 | one live card |
| S2 | Minion count and cap: `wantMinions` is a guess (skill level, skeletons 12, mages 4, revives 8); real caps come from skills.txt params (`Param` columns of Raise Skeleton, Skeletal Mage, Revive), which the code never read (U) | necro.go `wantMinions` comment | small, offline |
| S3 | Curses beyond Amplify Damage, Weaken and Lower Resist: Decrepify (slows and weakens, the review's "later"), Terror, Dim Vision, Iron Maiden, Life Tap, Confuse, Attract need a cast rule in `curseFor` (when, on what) and a state number each; today `curseNames` recognises them and nothing casts them. Also the state read-back: Amplify state 9 was never seen after a cast, so a 30 s cast memory stands in, and Lower Resist has no known state | necro.go `curseFor`, `curseStates` | medium, needs a state read live |
| S4 | Layout keys: only F1 to F8 exist, the summoner needs eleven bindings (Weaken, Lower Resist, Fire Golem are unbound, so `usable()` skips them and Clay Golem keeps the golem slot). A popup or a second key row, or swapping by phase | profiles.json layout | small |
| S5 | Golem choice: `golemLadder` names "Fire Golem" while skills.txt and the catalog row say `FireGolem` and the plan tables `FireGolem`; whether `KnownSkills` ever matches it is U (check `cat.Skill` names live). | S6 | Corpse handling: Revive, Raise and Corpse Explosion compete for the same corpse (`tried` set, `planSummon` before `corpseExplode`); bosses cannot be raised (U); a corpse reservation for Revive on a strong monster, and no Corpse Explosion on a corpse an unraised mage needs. | S7 | Mana budget: skeleton 6 mana +1 per level, mage 8 +1, golem 15 +3, Fire Golem 50 +10, Revive 45 (skills.txt, V); an army of 12 skeletons plus mages plus golem exceeds the pool at clvl 20 (V live: 71 down to 14). | S8 | Positioning: minions need space, stay behind the army, step back after a teleport, narrow corridors (Maggot Lair); kolbot's `raiseArmy` and the Koolo class files are the idea (read only, no code copied: GPL) | docs/classes/necromancer.md section 8, public-d2-bots-2026-11-19.md | medium |
